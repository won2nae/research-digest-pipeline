### 반복 생성 루프 — 근본 원인 조사와 최종 해결 (2026-11-01)

처음엔 2026-10-30 1건만의 돌발 사고로 보였으나, 조사해보니 **거의 상시적으로 발생하는 문제**였음이 드러남. 해결까지 3단계 시행착오:

1. **1차 시도 — `no_repeat_ngram_size=4` (생성 자체를 하드 제약)**: 같은 4-gram이 두 번 이상 나오면 모델이 다른 토큰을 선택하도록 강제. 같은 프롬프트로 2회 테스트했는데, 반복은 막혔지만 **매번 다른 방식으로 더 나쁘게 깨짐**:
   - 1회차: "시니어 애널리스트가 직접 해야 하는 작업"이라며 작업을 거부하는 JSON 에러 메시지만 266자 생성.
   - 2회차: "주주환元", "증기"(증시 오타), 한자가 불규칙하게 섞인 비문이 3,416자 생성됨.
   → **폐기**. 하드 제약이 모델의 정상적인 선택지를 막아버리면서 더 심한 실패로 이어짐.

2. **2차 시도 — temperature만 조정 (카테고리별 0.5~0.65로 분리)**: 매크로/채권은 수치 일관성을 위해 0.5로 낮추고, 섹터/투자전략은 서술 다양성을 위해 0.65로 올림. temperature만 바꿔서 같은 프롬프트로 테스트했는데, **0.65에서도 동일한 반복 루프가 그대로 재현**("KOSPI 선행 PER은 4.4배, EPS는 1,349.5pt이다." 수십 회 반복). → temperature 변경 자체는 (별개 기능으로) 유지했지만, 반복 문제의 해결책은 아니었음.

3. **최종 해결 — 생성 후 문장 단위 near-duplicate 탐지 및 절단**: `repetition_penalty`/`no_repeat_ngram_size` 등 생성 단계 파라미터로는 근본 해결이 안 된다고 판단, DART 때와 같은 방향("프롬프트/디코딩으로 안 되면 코드로 강제")으로 전환.
   - 문장 단위로 쪼갠 뒤 `difflib.SequenceMatcher` 유사도로 비교. 완전 동일 문장뿐 아니라 "트럼프 대통령은" ↔ "트럼프 대통령이 집권 2년차 중간평가 및 의회 권력 재편 분기점에서"처럼 **표현만 바뀌는 변형 반복**까지 잡기 위해 exact match가 아닌 유사도 기반으로 설계(단순 `no_repeat_ngram_size`나 정규식 백레퍼런스로는 이런 변형을 못 잡음).
   - 최근 10문장 중 유사도 0.55 초과가 3개 이상이면 반복 루프로 판단, 그 루프가 시작된 지점(가장 오래된 유사 문장)에서 잘라냄.
   - 과거 output 28개 파일 + 운영 중인 정상 리포트 다수에 적용해 **오탐 0건** 확인 후 적용.
   - `scripts/local_llm.py`의 `trim_runaway_repetition()`, `ask_local()` 리턴 직전에 항상 적용.

### 반복 탐지 2차 보완 — 마침표 없는 불릿 반복은 못 잡던 문제 (2026-11-01, 같은 날 추가 수정)

위 1~3단계로 끝난 게 아니었음. DART 통합을 실제 `main()`으로 끝까지 돌려보는 end-to-end 테스트 중, 투자전략 리포트가 ⑫번부터 ㊳번까지 "SK하이닉스 주주환원", "미국 중간선거 이란" 등 몇 개 블록만 계속 되풀이하는 걸 발견. 그런데 **문장 단위 탐지기가 이걸 전혀 못 잡았음** — 반복되는 게 "- 삼성전자: 주주환원의 세부 계획 부재에 실망 매물 출회"처럼 마침표 없는 불릿 목록이라, 마침표 기준 문장 분리기가 이 구간을 통째로 하나의 "문장"으로 묶어버려 비교 자체가 안 됐던 것.

- **1차 보완(실패)**: 줄바꿈도 문장 경계로 추가(`\n`도 분리 기준에 포함) → "- Intel 주가 하락: 21%" / "- SanDisk 주가 하락: 5.3%"처럼 **같은 템플릿에 다른 회사·숫자만 바뀌는 정상적인 나열**까지 오탐(유사도 0.70). 템플릿 공유 때문에 짧은 불릿은 유사도가 쉽게 높게 나와서 폐기.
- **2차 보완(실패)**: `##`/`###` 헤딩 텍스트만 비교(불릿 제외) → 오탐이 더 심해짐. "매크로(경제)"라는 제목이 파일 맨 위에 2번 나오는 기존 구조(`## 매크로(경제)` + 모델이 쓰는 `# 매크로(경제)`)부터 걸리고, "관련 리포트"·"원자재 코멘트"처럼 **서로 다른 내용에 재사용되는 정상적인 소제목 템플릿**까지 다수 오탐(87건).
- **최종 해결**: 헤딩 텍스트 + 그 아래 본문 앞부분(250자)을 합쳐서 비교, 유사도 0.85 초과 + 이전에 이미 2번 이상 나온 헤딩일 때만 반복으로 판단. "같은 제목, 다른 내용"(정상)과 "같은 제목, 같은 내용"(진짜 반복)을 구분할 수 있게 됨. 과거 전체 파일에 재검사해 오탐 0건, 기존에 못 잡았던 진짜 반복만 9건 추가 발견.
- 기존 문장 단위 탐지(마침표 기준)와 이 헤딩 단위 탐지를 **같이 돌려서 더 앞쪽에서 반복이 시작된 지점을 기준**으로 자르도록 `scripts/local_llm.py`의 `trim_runaway_repetition()`을 재구성 (`_sentence_loop_cutoff` + `_heading_loop_cutoff`).

### DART 에이전트 — 재무비율 계산 추가 + 독립 산출물

- `dart_mcp_server.py`의 `dart_financial_summary`가 원시 계정값만 주던 걸, 영업이익률·순이익률·ROE·전년대비(YoY) 성장률까지 계산해서 반환하도록 보완.
  - 재무상태표(BS)·손익계산서(IS/CIS) 계정만 걸러서 사용 — 자본변동표(SCE) 등 다른 명세서에 같은 계정명이 중복으로 나와 엉뚱한 값을 집어먹는 버그를 `sj_div` 필터로 해결.
  - 순이익 계정명이 보고서 기간마다 다름(분기=분기순이익, 반기=반기순이익, 연간=당기순이익) → 셋 다 인식해서 "당기순이익"으로 통일 표시.
  - YoY는 분기·반기 보고서에선 DART API가 전년동기 비교값을 안 줘서(연간만 제공) 계산 불가 — 마진·ROE는 모든 기간에서 계산되지만 YoY는 연간 보고서에서만 표시됨.
- DART 기업분석 결과를 `output/{날짜}/strategy.md`에 통합하는 것과 별개로, `output/{날짜}/dart_analysis.md`로 독립 파일도 생성하도록 추가 (별도 에이전트라는 걸 output에서도 바로 확인할 수 있게).
- 전체 파이프라인(`summarize.py main()`)을 실제로 끝까지 돌려 DART 기업분석(사피엔반도체·한미약품·SK텔레콤·KMW 4개 기업, 공시·재무제표 대조)이 정확하게 동작함을 확인.

## F. DART(전자공시시스템) 기업분석 에이전트 (2026-11-01 신설)

투자전략 리포트에서 다룬 기업이 실제 공시·재무제표 수치와 맞는지 대조하는 **별도 에이전트**를 multi-agent 구조로 추가. 단일 파이프라인에 기능을 끼워 넣는 대신, 독립된 Claude 서브프로세스(`scripts/dart_agent.py`)가 전용 MCP 도구(`dart_mcp_server.py` → DART Open API)를 호출해 조사하고, 그 결과를 투자전략 생성 단계가 참고하는 구조.

| 문제 | 조치 |
|---|---|
| `.env`의 `DART_API_KEY` 값이 따옴표로 감싸져 있어 42자로 읽힘(정상 40자) → 인증 실패를 zip 파일 파싱 오류로 오인 | 정규식 뒤에 `.strip("'\"")` 추가. 키 자체는 출력하지 않고 `len()`·boolean만으로 진단 (Claude Code 자체 분류기가 키 일부 노출 시도를 "자격증명 노출"로 차단 — 자격증명 비노출 원칙 재확인) |
| `claude -p` 서브프로세스 실행 시 "DART MCP 서버가 연결되어 있지 않음" | `.mcp.json`이 프로젝트 루트에 있는데 cwd를 `scripts/`로 호출 — `subprocess.run(..., cwd=str(ROOT))`로 명시 |
| 프롬프트에 기업분석 결과를 끼워 넣어도 모델이 본문에 거의 반영 안 함 (4차례 실험: 운영 어댑터 / 베이스 모델 / 명시적 지시 문구 추가 / 지시를 데이터 바로 옆에 배치 — 전부 "공시"/"DART" 언급 0회) | 프롬프트 주입을 포기하고, 생성이 끝난 뒤 코드가 "## 기업 공시 검증 (DART)" 섹션을 직접 추가 (기존 "AI 종합의견"과 동일한 패턴) |

### DART 재무 추이 도구 추가 (2026-11-02)

"재무정보를 RAG로 구축해서 투자전략 생성 때 참고하면 좋겠다"는 제안에, 벡터
검색은 추천하지 않는다고 답함 — 재무 수치는 근사 유사도가 아니라 정확한
일치가 중요해서, 벡터 임베딩보다 회사명+기간으로 직접 찾는 구조화된 조회가
더 정확함. 대신 이미 쌓이고 있는 `DART/{회사명}/` 아카이브를 그대로 활용해,
DART 에이전트가 한 회사의 여러 분기 재무정보를 한 번에 비교할 수 있는
`dart_financial_trend` MCP 도구를 추가함 (`dart_client.list_cached_financials`).

- 분기 보고서 값이 "해당 분기까지 누적"이라는 함정(반기=1~6월 누적, 3분기=1~9월
  누적)이 있어서, 라벨에 누적 여부를 명시하고 에이전트가 혼동하지 않게 함.
- `reprt_code`가 숫자 순서와 분기 순서가 다른 버그(11013=1분기, 11012=반기라
  문자열 정렬하면 반기가 1분기보다 앞에 옴)를 발견해 명시적 순서 매핑으로 수정.
- 실전 테스트(2026-10-30)에서 효과 확인: SK하이닉스의 "3Q 매출 104.6조"가 리포트와
  캐시된 반기 데이터 사이 누적 기준 불일치 가능성을 스스로 짚어냄. 부수적으로
  LG에너지솔루션 리포트가 언급하지 않은 "횡령·배임혐의발생" 공시(10/14)를 찾아냄.

## G. 지식그래프 + 공개 채팅 (2026-11-04)

"재무정보를 RAG로 구축"에서 더 나아가, "지금 구조를 안 건드리고 지식그래프를 적용할 수 있나"는
질문에서 출발. 벡터 임베딩 대신, 이미 있는 DART corp_code(기업 canonical ID)를 축으로
`data/`·`output/`·`DART/`를 **읽기만 해서** 그래프를 뽑아내는 파생 레이어로 설계·구현함
(기존 파이프라인 파일은 전혀 수정 안 함, `vectorstore.py`와 같은 패턴).

- `scripts/build_graph.py` (신설): Company/FinancialPeriod/Report/Broker/DailyBriefing 노드,
  HAS_PERIOD/PUBLISHED_BY/MENTIONS/VERIFIED/INCLUDES 엣지. `networkx` 사용(Neo4j 등 DB 서버는
  혼자 하는 프로젝트엔 과함).
- 기업 언급(MENTIONS) 추출은 LLM 호출 없이, 이미 가진 corp_code 사전(3,979개)으로 단순 문자열
  매칭만 사용. 2글자 이하 회사명(SK, LG, CJ 등)은 오탐이 많아 매칭에서 제외.
- 과거 전체 이력(2007~2026, 4,724일)에 한 번 풀 백필 — 4분 31초, 노드 113,911개·엣지
  294,198개, `graph/kg.json`(로컬 전용, 50MB, gitignore 대상).
- 사이트 공개용은 최근 120일만 별도로 작게 뽑음(`--days`/`--out` 옵션 추가) — `site/data/graph.json`
  (3.2MB) + `site/data/digests.json`(기존에 이미 공개된 일별 브리핑 내용을 한 파일로, 1.3MB).
  `build_site.py`가 배포 때마다 같이 구움 → `run_daily.sh`에 자동으로 포함됨.

**공개 채팅** (`site/chat/`, `site/api/chat.py`): 방문자가 자연어로 질문하면 Claude API가
`get_daily_briefing`/`search_briefings`/`company_lookup` 세 도구로 위 공개 데이터를 조회해
답변 (dart_agent.py와 같은 tool-use 패턴). 설계 결정:
- **벡터 RAG 대신 그래프+키워드 조회**: 숫자·날짜는 근사 유사도보다 정확한 조회가 중요하다는
  원칙을 여기도 그대로 적용.
- **로컬 Qwen 대신 Claude API**: 공개 기능이라 이 개인 서버를 상시 노출시키지 않는 쪽을 택함.
  Vercel Python 서버리스 함수(`site/api/*.py`)로 배포, API 키·그래프 등 비공개 데이터는 전혀
  노출 안 됨.
- **요청마다 과금되므로 남용 방지 필요** — Upstash Redis REST API로 IP당 하루 20건 제한
  (환경변수 없으면 로컬 테스트용으로 통과시킴, fail-open).
- 로컬에서 데이터 조회 함수 3종 + HTTP 핸들러(에러 처리, 메시지 길이 제한, 빈 메시지 거부)까지
  전부 단위 테스트 완료. 실제 Claude API 호출 왕복은 API 키가 있어야 해서 미검증 — **배포 전
  수동 설정 필요**: Anthropic API 키(Claude Code 구독과 별개, console.anthropic.com에서 발급
  필요) + Upstash Redis 무료 티어 + Vercel 환경변수 등록.
